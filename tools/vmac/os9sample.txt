# tools/vmac/os9sample.txt — the fixtures replayed on emulated Mac OS 9.2.
#
# Deliberately much smaller than sample.txt, which is the Mac Plus set. Each
# fixture here costs a whole boot of Mac OS 9 (~110 s on an idle host, plus a
# 2 GB image copy), where the Mini vMac harness replays a whole set inside one
# boot. So this samples for BREADTH OF FORMAT, not for the memory-budget
# spread that sample.txt exists to exercise: the 1 MB floor is a System 6
# question and the OS 9 machine has 512 MB.
#
# Selection rule: the smallest fixture of each format, plus three cases the
# size-ordered pick would have missed —
#
#   derived-DDT.sit          the smallest fixture carrying a real RESOURCE
#                            fork, which is what the whole M10 File Manager
#                            saga was about and what a data-fork-only sample
#                            never touches;
#   derived-XferIt_1.5b4.sea a self-extracting archive, and at 285 KB by far
#                            the largest thing here;
#   derived-DandStoQIF2.sea  DiskDoubler, which is DETECT-ONLY by the brief.
#                            The correct outcome is a clean refusal with
#                            nothing written, and that is checked: the harness
#                            passes it only when the Mac and the Linux engine
#                            BOTH produce nothing. Most `.sea` fixtures in the
#                            corpus turn out to be DiskDoubler or Now Compress
#                            rather than StuffIt, which the extension hides.
#
# Run:  tools/vmac/os9.py --list tools/vmac/os9sample.txt -o <dir> --launch
#
# Every entry is checked byte-for-byte, both forks, against the same engine's
# Linux output — see verify_output() in os9.py. Results in FORMATS.md.
